# MacRemote — Final Design Specification

> **Provenance.** This document is the synthesis output of a judged design competition run on **2026-07-01**. Five complete directions were produced and scored by five judges (commercial, platform purist, power operator, prosumer first-impression, parity auditor). Rank-point tally (higher = better): **mission-control 21 · guided-operator 19 · system-utility 15 · dense-console 11 · glass-expressive 9**. **Winner: `mission-control`.** This spec starts from Mission Control's skeleton, resolves every fatal flaw any judge raised, and deliberately grafts the judge-recommended ideas from the other four directions. Where judges conflicted, the decision and rationale are recorded in §1.2. The companion rulebook is `DESIGN-GUIDELINES.md`.
>
> Parity contract: all **200** audited items were mapped in §7 on that date. A feature may be removed only by a dated entry in the §1.2 decision log; §7 rows for removed features are then deleted, so the section counts in §7 headings are the original audit totals. Platform target: **macOS 26 SDK (26.5), Liquid Glass**, runtime macOS 26/27 — verify every API named here with the pinned build (`SDKROOT=/Library/Developer/CommandLineTools/SDKs/MacOSX26.5.sdk`, `.macOS(.v26)`, tools-version 6.2).

## 1. Thesis and decision log

### 1.1 Thesis (from the winner)

MacRemote keeps exactly one precious object alive: **this Mac's remote connection** — the state machine Off → Local → Public that, when public, produces the link you paste into an MCP app such as ChatGPT or Claude. The app is a cockpit around that object: one hero **Connection** surface where a single morphing glass object carries the state and the public URL; a calm five-item sidebar whose decision count lives on Requests and whose separate Tools count reports new discoveries (D54); a floating, non-activating **Approval window** as the security interrupt; and utility-grade depth discipline — all 200 capabilities survive, but admin machinery (custom domains, credentials, Full Disk Access forensics, verification) lives exactly one level below a quiet surface, reached from the status object it serves. The current app narrates its security model on every screen; this design *shows* the state and saves the narration for the moments a decision is actually being made.

| D18 | **Server-stop semantics for pending requests.** | Pending requests **resolve to Denied with reason "Server stopped"** (one grouped Activity line; history rows keep the reason). | D21 | **Automatic MCP discovery vs consent.** | Config-only refresh at launch/activation uses stat + read with zero subprocess/network. Import and share remain explicit user acts. The pass also reconciles persisted import ownership: when a readable config no longer defines a server, its imported tools and grants are removed; a configured-but-offline server is preserved. Direct CLI endpoints, runtime-only discovery, and legacy rows without explicit ownership are not auto-removed. Explicit Import/Refresh stamps the chosen config; endpoint equality never infers ownership. CLI full probing stays button-only. | Security wins on substance (no scan-without-consent for probing or CLI enumeration); discovery also prevents removed configs from leaving callable stale bridges without risking ambiguous legacy/manual imports. |
| D19 | **Connection card layout** (2026-07-03) — the three full-width stacked cards wasted horizontal space when collapsed. | **Collapsed cards render as compact `StatusTile`s in an adaptive `LazyVGrid`** (min 240, max 420, `Space.s4` gaps); opening a tile expands that card **full-width below the grid**. Expanded content is byte-for-byte the previous card content — D1, the deploy form, and the Verify verbs are untouched. Tiles keep the Card material recipe (quaternary fill, concentric 12, never glass); hover is a quiet fill shift, no lift. | HIG: content cards use standard materials, adaptive grids reflow with the window (Layout); Liquid Glass stays out of the content layer (Materials). |
| D20 | **Cloudflare Access removed** (2026-07-03; cleanup safety revised 2026-08-30) — the Access-gated sign-in modes were too convoluted to set up and blocked Claude.ai connectors at /mcp. | **Three sign-in methods, all enforced by MacRemote's own server:** OAuth Client Secret · Dynamic OAuth · **Single Header** (a MacRemote-generated bearer token sent as one `Authorization` header; validated by `OAuthCoordinator`, not the edge). Persisted Access modes migrate to Dynamic OAuth. A deploy may detect a leftover Access app and warn, but **never deletes it without durable ownership proof**; name and domain matches are not proof. Deploy stages drop *Protect endpoint* (four stages). | Federico's call 2026-07-03. One enforcement surface (the app) instead of two (app + Cloudflare Zero Trust); remote deletion must fail closed when ownership is ambiguous. |
| D22 | **Native tool backend** (2026-07-05) — first tools implemented in Swift, no subprocess. CLI-DISCOVERY-SPEC §3.3 asserted "There is no new tool type." | **Adopted as `ToolBackend.native` for the built-in File Transfer group only.** The generic-CLI and bridge machine is unchanged; native is a closed, code-defined `filesystem_*` set that never touches `tools.json` and never accepts a user-authored argv. User/preset/scanned tools remain process- or bridge-backed. | The File Transfer tools need binary-safe chunked I/O and artifact staging that a delegated CLI can't give safely; a fourth backend is narrower and more auditable than shelling out to `cat`/`dd`/`zip`. CLI-DISCOVERY-SPEC §3.3 updated in the same change to scope its "no new tool type" claim to the scan-to-add path. |
| D23 | **Serving file bytes to remote apps** (2026-07-05) — inlining bytes in tool results vs. a fetchable link. | **Short-lived artifact link.** Download tools return a handle; MacRemote's server adds a `download_url` on an unauthenticated `/artifact/<token>` route (256-bit token, 10-minute expiry, 3 downloads, 512 MiB cap, rate-limited, `no-store`, purged on server stop). Bytes never ride inside the MCP result. | Large binaries don't belong in a JSON-RPC result; a capability-token link keeps the bearer surface unchanged while giving the app a normal HTTPS download the public link already reaches. |
| D24 | **Token lifetimes** (2026-07-05) — fixed vs. user-tunable. | **User-configurable in Settings › Security.** Sign-in access token 15 minutes (default) / 1 hour / 8 hours / 24 hours; refresh 24 hours (default) / 7 days / 30 days. Changes affect only newly issued tokens; refresh rotation is unchanged. | Apps that can't refresh in the background need longer sessions without forcing everyone off the safe default; the picker keeps "shorter is safer" honest instead of hardcoding one trade-off. |
| D25 | **Execution concurrency limit with graceful load-shedding** (2026-07-05; revised 2026-07-29) — after three iOS-client stress runs opened many tool calls at once (each shelling out to a child process), unbounded burst traffic could spawn runaway process trees on one Mac. | A single global `ToolExecutionLimiter` caps concurrent executions at **8**, acquired **after** approval. A call that can't get a slot within 3 s **fails fast** as an `isError` result with `reason:"unavailable"` ("Server is busy…") — it is never queued indefinitely. The same limiter bounds synchronous calls and Background Task workers. | A bounded limiter with fast-fail load-shedding protects the Mac without an unbounded queue, which would turn overload into unbounded memory and latency. Acquiring the slot *after* approval means a pending human decision never holds a slot, so approvals can never starve execution capacity. |
| D26 | **MCP error model unified to 2025-11-25** (2026-07-05) — earlier code mixed protocol errors and execution failures; an invalid argument could return as either. | Input-validation and runtime failures are **tool-execution errors**: a normal result with `isError:true` plus a machine `reason` code on `structuredContent` (`outputSchema` enum: `ok / nonzero_exit / timeout / output_limit / killed / invalid_argument / not_approved / unavailable / internal_error`). **JSON-RPC errors are reserved for the envelope**: `-32600` malformed request · `-32700` bad JSON · `-32601` unknown method · `-32602` unknown tool / bad params / bad cursor · `-32603` internal. Unknown notifications and `notifications/cancelled` return `202` with no body. | A client can self-correct a bad argument only when the failure comes back as a tool result it can read, not a protocol fault that aborts the call. One contract — result-with-`reason` for "your call failed", JSON-RPC error for "your message was malformed" — matches the 2025-11-25 spec and removes the ambiguity. |
| D27 | **Large tool output spills to a download link** (2026-07-05, corrected 2026-07-09) — a result must stay below the host's file-diversion threshold, but some tools legitimately emit much more. Builds on D23. | `ProcessRunner` retains the first **100,000 bytes** inline and simultaneously spools the complete bounded stdout to a mode-`0600` temporary file when it grows beyond that point. The MCP result keeps a UTF-8-safe head of at most **48,000 bytes** and the whole `CallToolResult` is capped at **120,000 bytes**; MacRemote appends a `resource_link` plus size and SHA-256 for the preserved output. `truncatedStdout:true` means the inline field is a head. It keeps `reason:"ok"` when the complete stream was preserved; `reason:"output_limit"` means the configured hard cap actually lost bytes, and a post-execution preservation failure is `internal_error` while the exit status stays authoritative. | The envelope remains small and parseable without conflating presentation truncation with data loss. Reusing D23's capability-token store preserves full output for 10 minutes / 3 downloads while keeping bytes out of JSON. |
| D28 | **Public-link auto-recovery watchdog** (2026-07-05) — the `cloudflared` process behind a public link can die while the local server is healthy; the old behavior left the link dead and the status misleading. | `TunnelWatchdog` health-checks the local origin and the tunnel process; on an unexpected stop it restarts the public-link process with **exponential backoff (1→32 s, ×2, capped)** for up to **5** consecutive attempts, surfaces a truthful **Reconnecting** status (attempt N) throughout, and gives up with a failure message + notification after the ceiling. A user-initiated Stop Sharing is never treated as a failure. | For the **Your Domain** case the public hostname and DNS are stable, so restarting the local process transparently restores the *same* URL — safe and invisible to connected apps. Backoff + a hard ceiling avoid a hot restart loop, and the Reconnecting status honors the truthful-status rule (no fake "all green") instead of showing Running while the link is down. |
| D29 | **Checked numeric argument parsing is a security invariant** (2026-07-05) — remote arguments are attacker-controlled JSON, and the MCP server runs in-process, so an unchecked `Int(someDouble)` trap would crash the whole app. | Every JSON-number→Int conversion on the request path goes through a **checked** path (`Int(exactly:)` behind a finiteness guard). A value that is non-integral, non-finite, or out of `Int` range becomes a normal `invalid_argument` tool-execution error — never a fatal conversion. This is a standing invariant, not a one-off fix. | A remote peer must never be able to crash the server with a crafted argument. Turning every numeric parse into a recoverable validation error keeps a hostile or buggy client from taking the public link down for everyone. |
| D30 | **`tools/list` returns the full catalog, no pagination** (2026-07-05) — an earlier change paginated `tools/list` at 60 tools with an opaque `nextCursor` (spec-legal). In practice Raycast, Minis, and Claude.ai fetch only the first page and never follow `nextCursor`, so with 257 shared tools every client silently saw exactly 60. This reverses that part of the earlier pagination decision. | `tools/list` returns the **entire** shared catalog in one response and never emits `nextCursor`. The server issues no cursors, so any `cursor` a client sends is stale/unsolicited and is **ignored** (full list returned), never answered with `-32602`. | "Feature parity is sacred" — a shared tool that no real client can discover is worse than a large response. The catalog is small enough (a few hundred entries) to serve inline well within limits, and honoring pagination only helps clients that implement it, which the ones we target do not. Cursors remain opaque server-issued tokens per spec; we simply issue none. |
| D31 | **NotesCTL gets a curated safe surface plus a full-fidelity escape hatch** (2026-07-09). | Add the **Notes** category and `set.notes`, containing **34** NotesCTL tools: **32 read-only** diagnostics/read helpers, one write-capable Full Disk Access settings opener, and one destructive Flexible Command (`notesctl_run`). The fixed tools cover safe, non-file-writing reads; launches, exports to disk, attachment copies, and every mutation stay behind the broad adapter's approval gate. The adapter passes exact argv plus optional stdin with no shell and keeps the complete CLI command surface addressable, including deep-only generalized `edit`. | A model gets high-quality schemas for routine reads without pretending NotesCTL's complete command grammar is narrow. One approval-gated adapter preserves parity for new and advanced commands without requiring MacRemote releases to mirror every flag immediately. |
| D32 | **Product connection paths** (2026-07-11; superseded 2026-07-29). | Historical developer-mode transport guidance is retired. MacRemote has exactly two product connection paths: **Local**, through its loopback server for apps on this Mac, and **Public**, through the app-managed Cloudflare link for remote devices. ChatGPT on the public path uses Dynamic OAuth with Dynamic Client Registration. There is no third product mode. Anthropic Full Test is optional client verification over the Cloudflare public link, never a transport. | A third transport path creates a false product state and splits the sign-in model. Local and Public already cover the product's connection contract without adding navigation, lifecycle, or transport state. |
| D33 | **Stable tool identity, permission continuity, and large-catalog recovery** (2026-07-11). | One lowercase ASCII letter/digit/underscore ID (max 64 characters) is the persistence key, runtime lookup key, widget action target, and public MCP `name`; there are no opaque hash-only IDs or second internal ID, and deterministic hash suffixes appear only when normalization, length, or an exact collision requires one. Always Allow binds stable OAuth trust ID + semantic tool ID + security fingerprint. OAuth reconnect/token refresh is inert; a changed security contract or recreated tool asks again. `tools/list` stays complete and adds a deterministic revision; `macremote://catalog/v1` provides compact discovery; unknown-tool errors point clients back to both. The one-time dev migration is journaled, backed up, preserves Not Shared choices, clears unprovable legacy ID-only grants, and leaves OAuth clients/tokens alone. | Friendly IDs solve stale references only if every layer agrees on the same identity. Fingerprints preserve normal OAuth continuity without letting a familiar name authorize changed behavior. The additive manifest helps weak clients rediscover tools without weakening the standard MCP catalog or cross-host compatibility. |
| D34 | **Cloudflare Browser Integrity Check blocks API clients** (2026-07-11) — the public host returned Cloudflare error 1010 for Python's default user agent before requests reached MacRemote. | Custom-domain deploy first reads the existing named tunnel and hostname DNS record and rejects a foreign owner. A same-name tunnel must be remotely managed and proven by an exact tunnel DNS target or an existing ingress for the hostname; its name or a DNS comment alone is insufficient. It then ensures one exact-hostname Configuration Rule with `set_config {bic:false}` before legacy cleanup, tunnel creation/configuration, or DNS writes. Creation or repair proves `Zone -> Config Rules -> Edit` rather than mistaking Read for Edit; an already-correct last rule is a safe no-op. It uses a stable ref, appends or patches only its own rule, and forces it to last precedence; unrelated rules and the rest of the zone are untouched. DNS ownership is re-read immediately before mutation to block replacement races. | Requiring `curl` merely hid a hostname-wide failure that also blocked health and OAuth discovery. BIC is a browser heuristic, not MacRemote's auth boundary; exact-host scoping restores standards-based HTTP clients without weakening OAuth, approvals, capability URLs, or rate limits. |
| D35 | **File-read chunks must fit real client transports** (2026-07-11) — a 37,606-byte read became about 97 KB after base64 and duplicated MCP fallback framing; MacRemote then clipped the inner JSON at 48,000 bytes. | `filesystem_read_file` defaults to 16 KiB and clamps every pre-EOF request to **1 byte...16 KiB raw bytes per call**, so even a legacy `length:0` request advances. Callers advance `offset` by `length_returned` until `eof`; whole-file transfer uses `filesystem_download_file`. An authenticated server regression requires a complete parseable response below 64 KiB. | The old 64 KiB raw limit conflicted with MacRemote's own presentation cap and common downstream 64 KiB boundaries. A conservative fixed chunk keeps binary round-trips reliable across hosts. |
| D36 | **Bridge results should not contain a redundant second MCP envelope or lose upstream information** (2026-07-11). | HTTP and stdio bridge `stdout` carries the assistant-visible upstream semantic payload: `structuredContent` first, otherwise a sole assistant-visible text block, otherwise the assistant-visible content-block array. A user-only block (`annotations.audience` contains `user` but not `assistant`) never enters unannotated stdout. A bare JSON text fallback structurally equal to `structuredContent` is omitted; other distinct, annotated, or multimodal blocks remain real outer MCP content. A bridge-only lossless JSON value preserves booleans, numeric 0/1, and large integer IDs. Upstream `_meta` and nonstandard top-level fields are preserved under collision-safe MacRemote result-meta namespaces. At the 120 KB transport cap, assistant-visible content, user-only content, and hidden metadata spill to separate artifacts; both content links keep their audience and `_meta` never becomes model-visible. The configured tool output limit remains a hard cap: excess context is omitted atomically with `reason:"output_limit"` and a stderr diagnostic. Upstream `isError` maps to failed execution while retaining the payload and context within that cap. MacRemote's outer envelope and `reason` schema stay uniform; tool-specific JSON remains tool-owned. | Models should not need `stdout.content[0].text` for redundant Paste/X-style wrappers, but convenience cannot discard valid MCP fields, strip MCP audience hints, or cross `_meta`'s model-visibility boundary. Lossless, generic normalization improves ordinary discovery without inventing product modes or pretending HabitCTL and PocketCTL share one domain schema. |
| D37 | **Read-later CLIs need one first-class category, and opening the large Tools catalog has become expensive** (2026-07-13). | Historical catalog expansion for GoodLinksCTL, Matter, and Readwise. The category and immutable launch snapshot remain; the Matter/Readwise catalog entries are superseded by D39. | Preserved as history. |
| D38 | **Preset counts can disagree with stable identity, and large app catalogs are impractical to add one row at a time** (2026-07-13). | A curated preset is already added when either its stable semantic tool ID is occupied or its executable-plus-argument signature matches an existing tool. One shared installation plan drives every count, **Added ✓** marker, and bulk write. Bulk adds skip occupied presets without overwriting them, continue with every genuinely new preset, and treat an all-existing selection as a successful no-op. In the Presets tab, related recipes group by app and each app header gets one **Add N Tools** action for its remaining recipes; fully added groups show disabled **All Added ✓**. Individual **Customize & Save** and **Just Add** actions remain. | Stable IDs are the product's identity contract (D33); a changed path or revised recipe cannot truthfully become a second tool with the same ID. Signatures still catch equivalent hand-added tools. Using both prevents a count that promises work the transaction will reject, while per-app bulk actions make 17–20-recipe integrations usable without hiding individual control or changing sharing and approval behavior. |
| D39 | **Catalog ownership and refresh** (2026-07-28; the blanket no-adoption clause for scan-provenance equivalents is superseded only by D56's narrow complete-provider rule). | Curated first-party CLI support is limited to Federico Viticci's RemCTL, NotesCTL, HabitCTL, PocketCTL, GoodLinksCTL, and Apple Frames CLI. Unchanged security fingerprints keep Always Allow; changed contracts ask again. Signature-equivalent custom or scanned tools are never overwritten except for D56's unique scan-provenance adoption. Apple Frames contributes seven bounded recipes plus one Flexible Command. | Ownership is a product fact, not a category guess. Exact stable IDs provide a safe provenance boundary for simple refreshes; signatures remain dedupe-only for user-owned tools. |
| D40 | **Federico tools use a sparse semantic surface, and current catalog state is authoritative** (2026-07-28; updated 2026-07-30 for RemCTL 1.6.1; supersedes D31 and D39 counts and refresh migration; **superseded by D53**). | Ship exactly **39 dedicated Fixed Commands plus six Flexible Commands**: RemCTL 8+1, NotesCTL 8+1, HabitCTL 5+1, PocketCTL 7+1, GoodLinksCTL 6+1, Apple Frames 5+1. Dedicated tools expose typed reusable intent and lower through declarative exact-argv recipes; supported mutations use CLI preflight, while Notes editing is preview plus revision-guarded apply. Every provider keeps one Destructive every-call Flexible Command, installed Not Shared, for advanced coverage (the every-call mark is a default and a consent gate, not a lock — see D49). A complete provider Update from Catalog refreshes current IDs, adds missing IDs, and retires obsolete provider-owned IDs. No compatibility aliases are kept while MacRemote has one user. | A small vocabulary is easier for agents to choose correctly than a dump of every subcommand. Reliable routine flagging deserves one typed intent; the broad command remains the escape hatch for uncommon workflows. Authoritative replacement keeps the single-user catalog simple and correct. |
| D41 | **Background Tasks and the 2026 MCP protocol era** (2026-07-29; the original four-seed list is superseded by D56). | Add Background Tasks as progressive disclosure inside Tools, never as a page, transport, or onboarding branch. A normal command tool may opt in; native tools never may. Imported tools inherit a server default unless their tri-state override explicitly enables or disables Tasks. Server headers expose the exact menu label **“Background Tasks · N tools”**, a default toggle, and **Clear Tool Overrides**; eligible rows carry a **Task** chip and the Filter menu gains **Background Tasks**. Existing matching installs of Codex Read-Only Exec, Codex CLI, Claude Code, and FFmpeg are seeded on once; newly added matching presets opt in immediately. Their one-hour timeout seeds remain authoritative, while the editor supports **1 second–24 hours**. A tool runs as a Task only for the modern `2026-07-28` protocol, a client advertising the Tasks extension, an available Task runtime/artifact store, and an effective opt-in; every other case runs the same call synchronously. ### 4.3 Address card (collapsed by default into a grid tile — D19; tile states mode + hostname + deploy state)

The collapsed tile's summary line is state-aware: "Cloudflare's helper isn't installed" / "Downloading Cloudflare's helper…" / "Checking the download." — the same `addressSummaryLine` the tile and the collapsed card share.

**Install and update are refused while the public link is running**, not merely greyed out. The buttons disable, and the underlying call still refuses with a stated reason rather than silently doing nothing: **"Turn the public link off before replacing Cloudflare's helper."** (removal has its own line — §5.7). Replacing the file a live tunnel launched from is the same hazard removal already refuses; the refusal is real, not drawn.

**Failure copy model (D44).** A failure never promotes a system error string to a headline. The headline is **fixed per failure kind** — "MacRemote couldn't install Cloudflare's helper." (download or install) · "The download didn't match what Cloudflare published, so MacRemote discarded it." (checksum or signature) · "Turn the public link off before replacing Cloudflare's helper." (tunnel running) · "The install was cancelled. Nothing was kept." (cancelled) · "MacRemote doesn't have a Cloudflare helper for this Mac's processor. Install it yourself and MacRemote will use your copy." (unsupported hardware) — and the technical reason renders **separately**, as a selectable `MonoValue` beneath it (GUIDELINES §4.1 voice rule 9: human sentence first, raw detail selectable in mono below). Settings ▸ General ▸ Cloudflare Helper mirrors this with a dedicated **Reason** row carrying the same mono detail, so the **Helper** value slot never holds a failure message.

Expanded: two radio rows — **Instant Link** ("a temporary trycloudflare.com address; changes every time you go public") and **Your Domain** ("a stable address on a domain you own"). The Your-Domain form follows the setup order literally: API Token `SecureField` + **What Your API Token Needs** + the caption (Wrangler's own sign-in also works; a pasted token takes priority and is never stored) → **Load Domains** + status → Domain picker → Subdomain field → live Hostname preview → **Sign-in method as a read-only row → "Change in Settings…"** (D11) → the ordered deploy-hint line (`customDomainDeployHint`) → **Deploy Your Domain** (disabled until a token is pasted or Wrangler is installed and the helper is present — button and hint agree). Load Domains and Deploy enable when either a token is pasted or Wrangler is installed; the adjacent sentence states which source they will use, and a signed-out Wrangler fails at operation time with a sign-in sentence. Without a pasted token, MacRemote asks `wrangler auth token --json` for Wrangler's current credential once per operation and keeps it in memory only. The chosen domain and subdomain, plus the last deployed account, zone, hostname, and tunnel IDs, survive relaunch (`CloudflareCustomDomainPreferences`); no API token does, and restoring them never deploys. A deploy keeps one secret, the key that runs the deployed link, in the Keychain, and a truth note under **Deploy Your Domain** says so (D73); with it, **Go Public** brings a deployed domain back without a token or Wrangler (and Settings › General ▸ **Go public at launch** can do so at every launch, D76), and changing the domain or subdomain deletes it. Deploying a saved address requires Cloudflare to still hold that exact tunnel: a missing or replaced tunnel stops before any Cloudflare write. A fresh install starts with an empty subdomain rather than guessing one. Deploy progress is **four named stages**: *Check Cloudflare access → Create tunnel → Configure DNS → Start* — a failure lands on its stage, a stage-specific human sentence appears first, and sanitized technical detail appears in a separate copyable mono disclosure. *Start* remains active until Cloudflare's helper reports a registered named-tunnel connection; process spawn alone is not readiness, and a bounded timeout feeds the existing reconnect supervisor. Token errors use the same structured requirements popover · post-deploy proof grid (Hostname / Tunnel / Sign-in) · **Copy Header** when Single Header is the sign-in method. A ⓘ popover holds the Why-Cloudflare explainer. Instant-link running state adds: "This address changes when you go public again."

Truthful status staged as a launch-control ritual — the exact opposite of the eight fake checkmarks it replaces.

## 8. Implementation requirements (non-visual, binding)

1. **Toolchain:** build with `SDKROOT=/Library/Developer/CommandLineTools/SDKs/MacOSX26.5.sdk`; `Package.swift` → `// swift-tools-version: 6.2`, `platforms: [.macOS(.v26)]`; zero `#available` checks; no 27-SDK-only APIs (`visibilityPriority`, `ToolbarOverflowMenu`).
2. **Tool editing** must preserve semantic identity and permission epoch transactionally; Always Allow remains active only when the security fingerprint is unchanged (D8/D33).
3. **Approval window** is non-activating; verbs are click targets + menu commands (D4). Pending-request resolution on server stop per D18. The 16-pending cap surfaces as a queue-footer note when hit.
4. **Readiness rows render their expansions in every state** (D1) — a code review finding a `state != .ready` guard around the FDA/Privacy expansion is a spec violation.
5. **No control approves more than one request** (D2).
6. **The MenuBarExtra never resolves a request** (D3).
7. **Glass budget is falsifiable** (see DESIGN-GUIDELINES §3): any `glassEffect(` outside `ConnectionHero` fails review.
8. QA states: both extremes of the macOS 27 transparency slider, Reduce Transparency, Reduce Motion, Increase Contrast, inactive window; Activity streaming under `.hard` edges; the 166-tool dataset at 1040×680 minimum.
9. **Catalog identity and recovery:** one semantic ID spans persistence/runtime/MCP; `tools/list` stays complete and carries its revision; `macremote://catalog/v1` remains readable; unknown tools fail with structured rediscovery metadata. Complete provider refresh may adopt only one unique scan-provenance execution-signature match, preserves sharing, and clears grants for both identities; custom and ambiguous matches remain untouched (D30/D33/D56).
