# MacRemote 1.1.1

MacRemote 1.1.1 fixes result cards that still appeared in ChatGPT after you
turned them off, makes loading your tools about seven times faster, and fixes
a set of smaller problems found in a full review of the app.

## Download

Download `MacRemote-1.1.1.zip` from the Club post. It unpacks to a **MacRemote
1.1.1** folder with the app, the Club guide, these notes, and the source code.

MacRemote 1.1.1 needs macOS 26 or later and runs on Apple silicon and Intel
Macs. It is signed with a Developer ID and notarized by Apple, so it opens with
a double-click.

## Updating from 1.1 or 1.0

Quit MacRemote, replace it in Applications with the new copy, and open it.
Your tools, connected apps, and settings carry over.

**If ChatGPT still shows cards you turned off,** open MacRemote's page in
ChatGPT's settings and choose **Refresh** once.
ChatGPT keeps the tool list it read when you added MacRemote, and a list read
under 1.0 still asked for a card on every tool.

## What's fixed

### Result cards stay off when you turn them off

ChatGPT keeps the tool list it read when you added MacRemote or last refreshed
it. If you added MacRemote under 1.0, that list still linked every tool to a
card, so ChatGPT kept drawing a "Completed" card after 1.1 turned cards off.
MacRemote's results already left the card out. Now the card itself checks:
when a result arrives without card data, the card draws nothing and takes no
space. ChatGPT may still show MacRemote's name above the result until you
refresh MacRemote in its settings once.

In **Settings › General ▸ Result Cards**, the switch for each tool family now
appears only while **Show result cards** is on. Before, the family switches
stayed visible and looked on while cards were off.

### Loading your tools is about seven times faster

Each time an app loads your tool list, MacRemote used to rebuild and hash every
tool's description. With 381 shared tools that took about 44 ms on the Mac.
MacRemote now builds the list once and reuses it until a tool or a setting
changes, so a load takes about 6 ms. Apps see the same list.

### Calls to command-line tools found by a scan start faster

Before each call, MacRemote checks that a scanned tool's program has not
changed since you shared it. It used to read the whole program every time,
which took 40 to 230 ms for large programs. It now reads it again only when
the file changes.

### Cards

- **Copy result** copies one line per row instead of one long run of text.
- A row's action no longer spins forever if you sorted the table or showed
  more rows while the action was waiting.

### Tool calls

- When an app cancels a call, for example when you press Esc in Claude Code,
  the approval on your Mac goes away and the tool does not run.
- Lists of numbers, such as several reminder IDs, reach bridged MCP servers
  as numbers, not text.
- A tool that crashes or is killed now reports that it was killed, with the
  signal, instead of an exit code.

### Apps and Always Allow

- Turning **Always Allow** on or off updates the app's counts and badge right
  away, not up to 30 seconds later.
- Read-only tools never ask, so their rows now say **Runs without asking**
  instead of showing an Always Allow switch that did nothing. The app's badge
  counts them, and the Tool Inspector says the same.
- The Apps page stays responsive with hundreds of tools, and **Revoke All**
  in a category saves once instead of once per tool.

### Settings and saving

- If macOS had locked one app's client secret, creating, replacing, or
  deleting another app's secret no longer removes the locked one from the list.
- Uninstalling one command-line tool while MacRemote runs no longer blocks
  adding, editing, or removing every other tool until you relaunch.

### Scanning and the Tools page

- A rescan no longer drops command-line tools that Homebrew links in from an
  app, such as `code`, `claude`, or `op`.
- The Tools page no longer reads every file inside your Claude extensions to
  check whether a scan is out of date, and its server pages redraw faster.
